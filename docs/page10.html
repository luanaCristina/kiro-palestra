Configurando MCP — na prática
📁 ~/.kiro/settings/mcp.json 
{
  "mcpServers": {

    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_PERSONAL_ACCESS_TOKEN": "${TOKEN}" }
    },

    "atlassian-cloud": {
      "url": "https://mcp.atlassian.com/v1/mcp",
      "env": {
        "ATLASSIAN_EMAIL": "seu@email.com",
        "ATLASSIAN_API_TOKEN": "${ATLASSIAN_TOKEN}"
      }
    },

    "smartbear": {
      "command": "npx",
      "args": ["-y", "@smartbear/mcp@latest"],
      "env": { "QMETRY_API_KEY": "${QMETRY_KEY}" }
    }
  }
}
3 chaves de uma boa config
1
command + args
Kiro inicia o server como processo local (npx, docker, ou binário).
2
env (secrets)
Sempre via ${VAR} — nunca tokens em texto puro.
3
Escopo mínimo
Token Jira só com permissão de leitura/escrita nos projetos do dia.
💡 Pro tip TW
Comece com 1 server. Adicione outros conforme precisar — não plugue tudo de uma vez.
