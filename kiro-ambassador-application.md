## 1. Tell us about your Kiro experience. What clients do you use, what's your typical use case for Kiro, what keeps you using Kiro instead of other tools?

I'm a Quality Analyst at Thoughtworks (since April 2022), and I use Kiro IDE as my primary development environment for both professional and personal projects.

**Clients I use:**
- Kiro IDE (desktop, macOS) for daily work
- MCP integrations with Jira, Confluence, Bitbucket, SonarQube, Figma, GitHub, and QMetry (SmartBear MCP Server)

**My typical use case:**

As a QA, I use Kiro in a way that's fundamentally different from how most developers use AI coding tools. My workflow centers on **Spec-Driven Quality Assurance** — I leverage Kiro's Specs to transform fragmented requirements (scattered across Jira stories, Confluence pages, and existing code) into formal, verifiable specifications with acceptance criteria and correctness properties.

My typical flow:
1. Connect to Jira and Confluence via MCP to read user stories and business rules
2. Use Kiro Specs to generate formal requirements with EARS-format acceptance criteria
3. Generate technical designs with correctness properties (things that must ALWAYS be true)
4. Generate property-based tests that verify those properties across hundreds of random inputs
5. Push test cases to QMetry via SmartBear MCP for traceability and reporting
6. Use Steering files to enforce testing standards across the team

I also use Hooks extensively — for example, automatically running tests on file save, validating accessibility compliance, and keeping documentation in sync with code changes.

**What keeps me using Kiro instead of other tools:**

I've used GitHub Copilot and Gemini Code Assist. They're good at generating code, but they lack **structure and verifiability**. What sets Kiro apart for QA work:

- **Specs** give me a systematic way to go from vague requirements to formal, testable specifications — no other tool does this
- **MCP** lets me connect ALL sources of truth (Jira + Confluence + code + QMetry) in one place, giving the AI complete context to generate meaningful tests
- **Steering** ensures the AI consistently follows our team's quality standards without me repeating instructions
- **Hooks** automate repetitive QA tasks (linting, test execution, doc updates) without manual intervention
- **Property-based testing integration** — Kiro naturally generates correctness properties and tests that cover edge cases I might miss manually

In short: Copilot autocompletes code. Gemini reasons well. Kiro does both AND adds the engineering rigor that QA demands. It's the only tool where I feel like the AI is working WITH my QA mindset, not against it.
